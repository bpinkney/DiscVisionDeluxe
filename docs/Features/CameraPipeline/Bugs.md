# Camera Pipeline — Bugs

## Active Issues

### ISSUE-1: Camera Calibration RMS 3.4274 — Needs Redo (High)
Target <1.0 (good), <0.5 (excellent). Current values: `fx=321.0, fy=320.6, cx=353.6, cy=281.8`.
This error propagates into every solvePnP call and is the root cause of ISSUE-2.
**Root cause:** Poor lighting during calibration caused noisy sub-pixel corner detection.
**Fix:** Redo calibration — see Tasks.md CAM-ISSUE-1 steps.

### ISSUE-2: World Z Axis Inverted in Ground Plane (Medium)
After applying `cameraToWorld`, disc positions show `kfZ ≈ -1.0 to -1.5m` when held at ~1m height.
**Root cause:** Poor intrinsics from ISSUE-1 → solvePnP error → wrong `cameraToWorld` Z row.
**Workaround:** `FireComplete()` clamps `linearPositionM.z = 1.0f` when negative.
**Fix:** Resolve ISSUE-1 → redo ground plane calibration → Z should self-correct.

### ISSUE-3: Real Throws Not Detected Without Establishment (Medium)
Disc must be held still ~0.5s before moving for KF to prime. Natural throws from outside the frame not reliably caught.
**Root cause:** Effective detection rate ~25–30fps. A fast throw gets only 3–6 frames; velocity variance threshold may not be met.
**Fix options (try in order):** See Tasks.md CAM-ISSUE-3 section.

### ISSUE-4: Detection Timeout Margin (Low)
At 30ms/frame × 60 frames = 1800ms worst-case drain. Timeout=2000ms (200ms margin). Existing scenes may retain old 500ms value.
**Fix:** Update `Detection Timeout Ms` to 2000 in Inspector for LiveCapture scene.

## Resolved / Hard-Won Facts

### SpinnakerNET_v140.dll is C++/CLI Mixed-Mode
Cannot be referenced as a managed assembly — always behaves as Native. Use P/Invoke against `SpinnakerC_v140.dll`. All bindings in `SpinnakerCAPI.cs`.

### Spinnaker DLL Dependencies
12 DLLs required (all Native, x64, Editor+Standalone). `vcomp140.dll` comes from `C:\Windows\System32\` — NOT in Spinnaker bin64. After adding/changing any native DLL: fully close and reopen Unity. A full PC reboot was needed once to seat the Spinnaker kernel filter driver. Find missing DLLs: Dependencies tool (drag DLL in, red entries = missing) + Process Monitor (`Process=Unity.exe`, `Result=NAME NOT FOUND`, `Path contains Spinnaker`).

### spinImageConvert Absent in Spinnaker 3.2
Does not exist in the C API. Configure camera to output Mono8 directly via GenICam node map: `SetEnum(hNodeMap, "PixelFormat", "Mono8")` in `InitCamera()`. No runtime conversion needed.

### TextureFormat.R8 Displays as Teal/Cyan in Unity 6 URP
Not grayscale. Preview texture must use `TextureFormat.RGB24` with manual byte expansion (each Mono8 byte → R=G=B). Raw byte[] passed to AprilTagDetector stays as single-channel Mono8 — do not expand there.

### Emgu CV cvextern.dll Meta File
NuGetForUnity installs managed `Emgu.CV.dll` but NOT `cvextern.dll` (~80MB native). Must be placed manually in `Assets/Plugins/EmguCV/`. The .meta file auto-generated by Unity may be nearly empty — write it explicitly: Native, x86 UNCHECKED, Editor (CPU x86_64, OS Windows), Win64 (CPU x86_64), all others off. Full Unity restart required.

### libusb-1.0.dll Hidden Dependency of cvextern.dll
Symptom: `TypeInitializationException` for `ArucoInvoke` even after cvextern.dll is correctly configured. Source: libusb GitHub releases VS2019/MS64/dll/libusb-1.0.dll. Same plugin settings as cvextern.dll. Full restart required.

### Emgu CV 4.12 API — Three Gotchas
1. Dictionary: use integer cast `new Dictionary((Dictionary.PredefinedDictionaryName)20)` — enum names for AprilTag36H11 are missing.
2. `ArucoDetector` class does not exist — use `ArucoInvoke.DetectMarkers(mat, dict, corners, ids, detParams, rejected)`.
3. `new DetectorParameters()` zero-inits all fields; OpenCV asserts `markerBorderBits>0`. Use `DetectorParameters.GetDefault()`.

### solvePnP CopyTo Dimension Mismatch (Zero tvec Bug)
Symptom: all tvec values are (0,0,0) despite tags being detected.
Root cause: `rvecMat.CopyTo(new Matrix<double>(rvec))` creates a 1×N row vector, but solvePnP outputs a 3×1 column vector — `CopyTo` silently fails.
Fix: `new Matrix<double>(3, 1)` as solvePnP output; read with indexer `rvecOut[0,0]` etc.

### BayerRG8 at 522fps — USB Bandwidth Saturation
720×540×522fps ≈ 200MB/s causes rapid camera disconnect/reconnect. Reverted to Mono8 at 290fps. To revisit: USB host controller bandwidth check + `CvtColor(BayerRG→Gray)` + ROI resolution reduction.
